# ELF 심볼 조회 도구

`ft_nm`은 Linux 오브젝트 파일, 실행 파일, 정적 라이브러리에서 함수와 변수의 이름·종류·값을 읽어 내는 C 도구입니다. 링크할 때 어떤 함수의 정의를 찾지 못했다면, 각 오브젝트가 그 함수를 정의했는지 다른 파일에서 가져와야 하는지 확인하는 데 쓸 수 있습니다. 입력 파일을 실행할 필요는 없습니다.

## 직접 확인하기

Ubuntu 22.04 x86-64(WSL2)에서 GCC, GNU Make, GNU binutils로 빌드하고 검증했습니다. 저장소에 들어 있는 작은 오브젝트 파일로 두 가지 조회를 해볼 수 있습니다.

```sh
make
./ft_nm -u portfolio_audit/bin/fixtures/basic64.o
./ft_nm -P portfolio_audit/bin/fixtures/high64.o
```

첫 명령의 `U missing_external`은 이 오브젝트가 참조하지만 내부에 정의가 없는 이름입니다. 둘째 명령의 `high_absolute A 100000123`은 절대 심볼(`A`)의 16진수 값이 `0x100000123`이라는 뜻입니다. `-P`에서는 이름이 맨 앞에 오며 32비트 범위를 넘는 값도 그대로 읽을 수 있습니다. [첫 번째 오브젝트의 소스](portfolio_audit/tests/basic64.s) · [64비트 값 예제 소스](portfolio_audit/tests/high64.s)

| 옵션 | 용도 |
|---|---|
| `-g` / `-u` | 외부 심볼만 조회 / 현재 파일에 정의가 없는 심볼만 조회 |
| `-a` | 기본 출력에서 숨기는 파일·섹션 심볼 등도 포함 |
| `-n` / `-r` | 심볼 값으로 정렬 / 정렬된 결과를 역순으로 출력 |
| `-P` | 이름, 타입 문자, 값, 크기 순으로 출력. 정의 여부와 크기에 따라 뒤쪽 필드 생략 |

## 파일에서 심볼까지

1. 파일을 읽기 전용으로 메모리에 매핑하고 처음 몇 바이트로 ELF와 일반 `ar` 아카이브를 구분합니다. 아카이브라면 멤버 헤더와 크기를 읽고, GNU 긴 이름 표가 있으면 멤버 이름도 복원합니다. 각 ELF 멤버는 자신의 시작 주소와 길이를 가진 입력으로 같은 파서에 넘깁니다. [입력 처리](src/io_unit.c) · [아카이브 순회](src/ar_parser.c)
2. ELF 클래스에 맞게 32비트 또는 64비트 섹션 헤더를 읽습니다. 정적 심볼 테이블(`SHT_SYMTAB`)에서 이름이 들어 있는 문자열 테이블을 찾아 각 심볼의 이름·값·크기·바인딩을 공통 구조체에 담습니다. [ELF 파서](src/elf_parser.c)
3. 심볼의 종류·바인딩·섹션 속성으로 코드 영역의 전역 심볼(`T`), 미정의 심볼(`U`) 같은 타입 문자를 정합니다. 선택한 옵션으로 필터링하고 정렬한 뒤 출력합니다. [타입 분류](src/sym_classify.c) · [필터·정렬·출력](src/sort_filter_print.c)

## 구현하면서 해결한 문제

- 처음에는 `-g`가 출력 문자를 보고 외부 심볼을 골랐습니다. 그 결과 외부에서 보이는 공통 심볼(`C`)과 간접 함수(`i`)가 누락됐습니다. 이제 ELF 바인딩을 기준으로 선별하며, 테스트에서 두 종류가 출력되는지 직접 확인합니다.
- `-P`의 32비트 변환 때문에 위 예제의 값이 `123`으로 잘렸습니다. 값과 크기를 64비트로 유지해 16진수로 출력하고 두 필드 모두 상위 비트가 남는지 검사합니다.
- 섹션 헤더 크기, 심볼·문자열 테이블의 범위, 심볼이 가리키는 섹션 번호를 확인하도록 보완했습니다. 여러 입력 중 하나가 잘못됐어도 뒤의 정상 파일 처리를 계속하면서 최종 종료 상태에는 실패를 반영합니다. [원래 오류를 재현하는 회귀 테스트](test/test_audit_regressions.py)

## 테스트와 지원 범위

빌드 후 Python 3로 다음 테스트를 실행합니다. 테스트는 `as`와 `ar`로 일부 입력을 새로 만듭니다.

```sh
python3 test/test_audit_regressions.py -v
```

Ubuntu 22.04에서 회귀 테스트 **6개가 모두 통과**했습니다. 입력 4종에 대한 옵션 조합 512건을 종료 상태와 출력 행으로 나눠 확인했습니다. `-z`가 들어간 256건은 두 도구 모두 거부했습니다. 두 도구가 정상 처리한 256건 중 88건은 심볼과 순서가 일치했고, 168건은 같은 심볼이 다른 순서로 나왔습니다. `ft_nm`은 이름 정렬 시 앞의 `_`, `.`, `$`를 건너뛰고 대소문자를 무시해 먼저 비교합니다. [옵션 조합과 입력 생성 코드](TestserMachine.py)

형식 오류와 종료 상태까지 GNU `nm`와 비교한 별도의 30개 사례에서는 21개 일치, 1개 부분 일치, 8개 차이를 확인했습니다. 차이에는 이름 정렬, `--` 옵션 종료 표시, 손상된 입력의 진단과 종료 상태가 포함됩니다. 입력 범위는 리틀엔디언 i386·x86-64의 ELF 오브젝트·실행 파일·공유 객체 및 일반 `ar` 아카이브입니다. 심볼 조회 대상은 정적 심볼 테이블이며 동적 심볼 전용 조회(`-D`)와 thin 아카이브 및 BSD 확장 멤버 이름은 지원 범위 밖입니다.
